# B27 format (RC3)
All integer fields are big endian. B27N: 4-byte magic, u8 profile 0–9, u32 original byte length, 32-byte SHA-256 of original bytes, payload. 0 store; 1–3 ternary Huffman; 4–6 LZSS; 7–9 LZSS then arithmetic coding. Within each group: raw, ASCII CVNSS records, packed Base27 records. Records: u8 tag (0 raw, 1 packed, 2 ASCII), u32 logical length, payload. Packed records use five base27 digits per 24-bit integer, most significant first, alphabet a–z then space. Tail uses actual digit count. Huffman: 256 u32 frequencies, deterministic weight/id ascending ternary merge, zero-weight dummy leaf when even, five trits per byte. LZSS: flag byte, least significant bit first; zero literal byte, one 16-bit distance and u8 length minus 3. Range: u32 LZ payload length, 24-bit arithmetic interval, six base3 digits per byte, context previous trit or start, initial counts 1, rescale at 4096, MSB-first output. B27T: magic, repeated u32 frame length and B27N frame (max original 256 KiB), zero u32, u64 total original length, u64 frame count, SHA-256 of concatenated original data. B27S legacy omits footer. B27F legacy uses raw DEFLATE for compressed profiles. SHA-256 is not authentication. This draft requires golden vectors and independent review before format freeze.
